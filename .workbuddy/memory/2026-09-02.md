## LifeOps RAG Golden Set 评测盘点（面试向）

盘点了 `Allthing/scripts/eval_rag.py` + `data/rag_golden_set.json` + `data/rag_eval/*.json`，
产出评测结论、面试官拷问应答话术、以及代码中发现的 4 个雷点。

### 事实基线（可直接背）
- Golden Set：50 题，5 类各 10 题（按菜系/区域/场景/小吃/综合），标注为 `expected_titles`（1-3 个/题），城市固定「中山」。
- 知识库：47 条 entries（`data/knowledge_snapshot.json`），题库比库还大 → 属功能验证集，非性能基准。
- 指标：Recall@5（macro 平均，按每题 expected 数归一）、Hit@5、MRR@5、avg_latency_ms。
- 实测（baseline → hybrid）：Recall@5 `0.7767 → 0.8067`（+3.9%）；Hit@5 `0.86 → 0.88`；MRR@5 `0.7313 → 0.7473`；延迟 `445ms → 944ms`。
- 分维度 Recall@5：按菜系 `0.567 → 0.700`（唯一显著提升）、按小吃 `0.90 → 0.95`、**综合 `0.917 → 0.883`（回归，主动讲）**、按区域/场景持平 0.80/0.70。
- Bad case：7 → 6（修好 q009/q028，新增 q027）。

### 代码中发现的雷点（面试前务必记住，答错即翻车）
1. **注释说 RRF，实际是线性融合**。`eval_rag.py:131` mode_label 写「RRF融合」，`hybrid_retriever.py` 实际是
   min-max 归一化后 `0.6×vec + 0.4×bm25`（alpha=0.6）。被问「RRF 还是加权」必须答加权。
2. **avg_top1_score 恒为 0（指标失效）**。eval 取 `results[0].get("_score")`，但 `search_knowledge`
   输出的 entry 里分数在 `confidence.score`，无 `_score` 字段 → 恒 0 → 汇总时 `if d>0` 过滤后为空。
3. **延迟 944ms 失真**。每次 query 都 `BM25HybridRetriever(entries, emb_matrix)` 重建 jieba 索引
   （47 条全量分词）+ 多调一次 Embedding API，索引未复用。真实增量开销远小于此。
4. **Milvus 可用时 hybrid/baseline 对比无效**。搜索 `_MILVUS_ENABLED` 分支先执行 `_milvus_rank` 并直接
   return，**完全忽略 mode 参数**；源码注释自己写明「BM25 混合模式仅降级管线有效」。这组对比只在降级路径成立。
5. 附加：Golden Set 为开发者自标注 → 用先验拟合检索器，指标系统性偏高（业界应从线上日志采样真实 query）。

### 业界对标（RAGAS / DeepEval / TruLens 主流口径）
- 检索层：Recall@K、MRR、NDCG@K、Context Precision/Recall（BEIR、MTEB 为公开基准）。
- 生成层：Faithfulness（答案声明是否都能被检索上下文支撑，生产阈值 ≥0.75）、Answer Relevancy（≥0.8）。
- 端到端：Answer Correctness、Noise Robustness（注入无关 chunk 后不答错）、人工分级标注、
  CI 拦回归（DeepEval/Patronus）。评测集常规规模 50-200 条。
- 关键认知：BLEU/ROUGE 只测字面相似，测不出「是否忠实于检索上下文」，RAG 场景不适用。

### 面试叙事定位
- 只评检索不评生成是**当前最大缺口**，用「已识别 + 计划补 RAGAS 生成层指标」来讲，别装作完整。
- 主动暴露综合类回归 + 延迟翻倍代价，比只讲提升可信。

4. `scripts/eval_rag.py`：修 `top1_score` 取 `_score` 恒 0 的 bug（真实字段 `confidence.score`）；
   支持 `--vector/--hybrid/--linear/--compare/--rrf-k`。
5. `requirements.txt`：补 `jieba` + `rank-bm25`。**这两个此前漏声明，导致降级管线 BM25 长期是死代码**
   （环境里根本没装，混合检索静默退化成纯向量）。

### 最终干净实测（2026-09-02 终版，修复 Milvus 探活超时 + 熔断后重跑，无 300s 污染）
50 题，降级管线（Milvus 未连上，走本地 BM25+向量）。默认 RRF k=5。
| 模式 | Recall@5 | Hit@5 | MRR@5 | Top1均分 | 延迟 |
|---|---|---|---|---|---|
| vector 纯向量 baseline | 0.7533 | 0.8400 | 0.7190 | 0.8680 | 433.6ms |
| hybrid RRF (k=5) | **0.8200** | **0.9000** | 0.7473 | 0.9013 | 337.8ms |
| linear 线性加权 | 0.8067 | 0.8800 | 0.7473 | 0.9300 | 334.8ms |

分维度 Recall@5（**决定 RRF vs Linear 胜负的关键**）：
| 维度 | vector | RRF | Linear |
|---|---|---|---|
| 按菜系 | 0.6000 | 0.7167 | 0.7000 |
| 按区域 | 0.7000 | 0.8000 | 0.8000 |
| 按场景 | 0.8000 | 0.8000 | **0.7000（回归 -12.5%）** |
| 按小吃 | 0.7500 | 0.9000 | 0.9500 |
| 综合 | 0.9167 | 0.8833 | 0.8833 |

**结论：RRF 优于 Linear，且更稳。**
- Recall/Hit 全面领先 Linear（0.8200 vs 0.8067；0.9000 vs 0.8800）。
- 决定性差异在「按场景」：Linear 从 0.80 掉到 0.70（-12.5%），RRF 持平。
  根因：Linear 用 min-max 归一化，BM25 无词命中（全0）时返回全 0.5 伪信号参与加权；
  场景类 query 关键词弱，正好踩中。RRF 按排名融合，天然免疫。
- Linear 仅在「按小吃」(0.95 vs 0.90) 和 Top1均分 (0.93 vs 0.90) 占优 —— 都是关键词强匹配类目。
- **综合类两者都从 0.9167 回归到 0.8833（-3.6%）**：两种融合一致回归 → 非融合策略问题，
  而是综合类 query 需 query 改写/多跳，单纯调融合救不了。主动讲。
- 延迟：RRF/Linear 都比 baseline 快（338/335 vs 434ms）→ 此前「延迟翻倍」是索引重建假象，已证伪。

**RRF 的 k 扫描（早期结论，终版已取 k=5）**：k 越小越好（语料小，k 大压平名次差异）。
| k | 1 | 5 | 10 | 20 | 60 |
|---|---|---|---|---|---|
| Recall@5 | 0.8200 | 0.8200 | 0.7900 | 0.7900 | 0.7900 |

### RRF 改造验收（改动已落地，默认 fusion="rrf"）
- hybrid_retriever：RRF 融合（默认）+ 线性加权（对照）；RRF 分除以理论最大值归一化到 [0,1]，
  下游置信度阈值（0.3/0.45/0.7）可复用。
- milvus_store：支持 RRFRanker(k) / WeightedRanker，纯向量单路（use_sparse）。

  但连不上时，首次探活失败即开熔断，避免每题卡 300s 连接超时）；默认 mode="hybrid"。
- eval_rag：修 top1_score 取 `_score` 恒0 的 bug（真实字段 `confidence.score`）；--compare 三模式全列 + 各自 delta。
- requirements 补 jieba + rank-bm25（此前漏声明，BM25 长期死代码）。

### 遗留（真正未做的）
- **降级管线 hybrid 丢掉精排信号**：`_bm25_fused_rank` 里 `_kw_boost/_tag_boost/_sem_tag_boost` 全置 0，
  而 `vector` 模式走的 `_hybrid_search` 有关键词/标签/语义标签三层 boost。等于 hybrid 只用两路、
  baseline 反而四路，对比不完全公平。修法：融合后叠加 boost 精排再排序。
- Milvus 路径应用层 `pop("_fused_score")` 后用本地余弦重排 → 服务端融合只影响召回集，不影响最终排序。
- 最大缺口仍是「只评检索不评生成」，未接 RAGAS Faithfulness/Answer Relevancy。
